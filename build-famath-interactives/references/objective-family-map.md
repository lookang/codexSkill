# Objective-to-interaction family map

Map by mathematical meaning rather than keyword alone.

| Family | Preferred model and interaction | Avoid |
|---|---|---|
| Counting and cardinality | tappable numbered objects, ten-frames/groups, last count as total | repeated passive dot pictures |
| Place value | labelled place chart, base-ten blocks, animated exchanges | digits without unit values |
| Number words | word segmentation, speech, numeral/place-value bridge | decorative highlighting only |
| Comparing sets | one-to-one pairing and visible leftovers | counting both sets without comparison |
| Ordering | baseline-aligned bars, tap/drag placement, animated selection | default correct order in help |
| Sequences and rounding | labelled number-line jumps, endpoints and midpoint | floating numbers with generic arrows |
| Factors and multiples | arrays, equal groups, factor chips, remainder test | times-table recall only |
| Whole-number algorithms | aligned columns, place-value blocks, regroup animation | unexplained carrying/borrowing digits |
| Fractions | equal partitions, sets, number bonds, equivalent scaling | unequal part sizes |
| Decimals | aligned place chart, hundredths grid, number line | counting decimal digits mechanically |
| Money | recognisable coins/notes, wallet target, tap and drag | text-only denomination strategy |
| Measurement | zero-aligned ruler, highlighted intervals/endpoints, unit labels | counting ticks instead of spaces |
| Area and perimeter | tiled regions, boundary tracing, decompose/recompose animation | formula-first hints |
| Angles | rays, vertex, protractor centre and 0-degree alignment | angle picture with no scale cue |
| 2D/3D geometry | property highlighting, construction steps, accurate solids/nets | labels that reveal the answer |
| Symmetry | draggable/reflected cells at equal distances, fold animation | centre line assumed sufficient |
| Data | tables and charts with headings, keys, units and scales | underdetermined missing values |

## Adding a new family

Add one manifest `kind`, a generator branch, one or more reusable model renderers, a family-specific worked sequence, and misconception-specific hints. Keep content data-driven so all six stages and future objectives reuse the same code.

Do not add a switch branch containing only a prompt and four choices. The visual model must carry the central mathematical relationship.

## Stage progression

Use approximately this sequence:

1. guided recognition with manipulable concrete/pictorial model;
2. guided representation or construction;
3. supported transfer to another example;
4. independent application;
5. misconception-sensitive variation;
6. short challenge or explanation check.

Vary values and surface context while preserving the target construct. Do not introduce a new construct merely to make the final question harder.
