# Verify preservation and reporting

1. Record original entry path, file hashes, screenshots and representative results before injection. Classify every output change as vendor addition, adapter addition, narrow domain hook, optional report UI, packaging change or explicitly requested improvement. Confirm other files retain their hashes. CSS and original model/navigation must remain unchanged in Integrate only except documented necessary hooks.
2. Exercise correct, incorrect, blank, revised, repeated-check, reset/new-case, support-before/after-check and restore paths as applicable. Compare original and integrated outputs, score policy, randomisation and animations. Test sliders with mouse/touch and keyboard commits; confirm they still control the original model.
3. Inspect in a real browser at desktop/mobile widths and inside a real 450px iframe. Confirm additions do not obscure controls or create new scroll/clipping issues. Preserve existing layout by default; identify existing limitations separately. Check keyboard and reduced motion for added UI.
4. Launch against a local mock LRS with synthetic full parameters through the preserved wrapper. Inspect actual received state and score statements, not just console logs. Assert no untouched-launch score, correct completion timing before Reports interaction, real score/max consistency, item coverage, preserved authored feedback, bounded meaningful history, no copied identity/auth/raw typing, and correct reset/restore state after cache formatting. For unscored activities assert no claim of achievement from mere control use.
5. Test missing launch parameters and transport failure without breaking source interactions. Keep test mocks and synthetic credentials out of the delivered package. Do not claim server acknowledgement based on “Submitted to SLS”; this sample logs after invocation. A bare DOMException does not establish a cause. “Missing agent” leaves attribution unverified.
6. Run the structural validator with default pinned hashes or a supplied known-working reference. Its regex/static checks do not validate payload execution or pedagogy. Inspect all actual changes and report local browser/mock-LRS verification separately from live SLS rendering and learner attribution.

The injection helper is a packaging scaffold, not a universal instrumentation engine. Test its output with an authored adapter before delivering it as integrated. A run with unchanged vendor hashes alone is not a successful learning-data integration.
